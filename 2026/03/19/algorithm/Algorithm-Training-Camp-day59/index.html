有事耽搁，博客简写：
Bellman_ford 队列优化算法（SPFA） 例题：卡码网 94. 城市间货物运输 I
bellman_ford之判断负权回路 例题：卡码网 95. 城市间货物运输 II
bellman_ford之单源有限最短路 例题：卡码网 95. 城市间货物运输 III

题目解析

94. 城市间货物运输 I

因为 bellman ford 算法中，可以发现很多的计算其实是可以忽略的，因为如果你打算根据节点 x，来尝试更新节点 y，那么节点 x 的结果你应该得先知道。那在最初始的时候，节点 x 到 y 的 val 还是 INT_MAX 。那么更新就是毫无意义的。

对此，可以使用队列，每次只将 被更新的节点 推入 队列中。这样就可以减少很多没用的循环

95. 城市间货物运输 II

接着上一题，但是不是每一天都像 第94题 一样，没有 负权环路，这个时候。

所以，对于 有负权回路的情况 我们就要通过限制循环次数，来解决问题。

对此，每次循环开始前，我们读取队列中 元素的个数，然后计数 使用了几次栈中的元素。
如果计数完全一次，说明一轮 bf 完成。

根据bf原理可知，N个节点 最多松弛 N - 1 次，这样就给了我们判断是否有 负权回路 标准

这道题我感觉从原理上来说，不使用 InQueue 也是可以出结果的。但是 我卡码网跑代码的时候 内存超限 了。所以还是使用了 InQueue

96. 城市间货物运输 III

再接着上一题，现在我不仅有 负权回路 ，还限制你的 经过的城市数量 k。

注意，这里是经过。
所以比如 k = 2 ，那么 1->2->3->4 其中 1 到 4 是满足条件 k <=2 条件的
可以发现，这个时候到目的地最远是 k+1 条边

那其实限制城市数量 k，说白了，就是最远经过 k+1 条边，才到达目的地。那么对此，只需要 松弛 k+1 次即可。

这个时候，我们只需要更改 上一题中 的 bf_count 条件 即可。

注意，上一轮中，我们 首先要 松弛 N-1 次
其次，最后 一次松弛结束后，队列里还有一个元素在，所以要有 1 次的冗余，防止出错
最后，因为 上一题 circle 的条件 是 超过。所以还要加 1 次。
所以总共 多了 2。

但是对于这道题，这两点都是不必要的，因为这次是要刚刚好踩到节点。所以我们并不用考虑队列残留，且不需要计算最后节点对其它边的影响

所以本题判断条件是 bf_count > k，或者更好理解应该是 bf_count >= k+1 表面恰好执行完 k+1 次松弛后，应该结束循环。

我遇到的问题

此外，这题当时还有一个问题困扰我：

我尝试 使用 InQueue 来防止在一轮循环中重复对 同一个 目标点 多次进入队列（这里我对于 InQueue的用法与卡哥中的解释有所不同）。
因为我认为 最核心的两句代码 minDist_copy[from] + edge.val < minDist[edge.to] 和 minDist[edge.to] = minDist_copy[from] + edge.val; 使用的都是copy的数值。在一轮中重复多次进入队列是没有必要的。
但结果没通过。

但是 一旦 我不使用 InQueue 就通过了。

我最后的想法

最后我苦思冥想终于想通了：

  1. 首先，在没有使用 copy 的时候，使用InQueue确实可以减少数据的重复计算，因为这个时候 minDist 是 及时更新 的
  2. 但是对于本题来说，因为 距离限制导致必须得一步一步更新，所以为了限制如卡哥举例的所有节点一步到位更新完毕，需要使用 copy 的数据
  3. 这个时候，在 copy 的基础上使用 InQueue 就出问题了：
    1. 因为每一轮栈中 往后添加的都是下一轮 要运算的节点
    2. 不妨假设 本轮初始 队列中已经有了节点 X
    3. 而在节点 X 之前，有节点 更新了 节点 X 的数值。那么节点X本该进入队列，在下一轮中进行运算
    4. 但是因为 InQueue 的存在，本轮 的 X 还没有出队列，所以 X 无法入队。这导致下一轮会 少计算一次。最终导致结果出错。
    5. （而对于 没有 copy 的情况来说，更新是及时的，就没有这个顾虑。所以对于 不使用 copy 的情况，可以使用 InQueue 减少计算）
