有事耽搁，博客简写：
最小生成树 prim、kruskal
例题：卡码网 53. 寻宝

原理解释

今天学习的两种算法都是用于 最小生成树的。
最小生成树：是连接所有节点的最小联通子图，即边最少且权重和最低的情况下，将所有的点连接起来。

那 看完 最小生成树的定义，可以很自然的产生两种思路：

  1. 关注于 节点； 想办法每次记录要添加到 最小生成树 中的节点（prim）
  2. 关注于 边：想办法将尽可能短的边塞进 最小生成树 中（kruskal）

prim

对于 prim 算法，我们想办法记录，每个节点 到 最小生成树 的

然后按照以下部分重复执行

  • 找到 距离 最小生成树 最近的节点
  • 将 该节点 添加 到最小生成树中
  • 更新所有 不在最小生成树中的节点 到 最小生成树 的距离

实现细节：

  • 要初始化 所有节点的 最小距离 为 无穷 ，或 INT_MAX
  • 由于一开始塞入谁到节点中都可以，所以直接考虑塞入 节点1
  • 总循环次数可以就是节点次数，因为一次循环塞入一个节点，那么最多就是 V 次循环
  • 在更新某个 节点j 的距离的时候，不用遍历全部的 在树中 的节点 再依次比较，只需要比较当前 最新添加到树中的节点 即可。因为老的节点都添加过了，那自然在前几轮的循环中，就已经比较过了，那么遍历就成了重复劳动。
  • 我的实现中，在更新距离的同时，直接寻找 距离最近的最小生成树

kruskal

与 prim 不同， kruskal 在尝试 将 最短的边塞如 树中

  1. 先将 所有的 edge 按照权重 从小到大 排序
  2. 然后 按顺序 尝试将 全部的边 塞入 集合中

    此时将 节点塞入 并查集 中，因为 并查集 可以高效判断

  3. 如果 当前边的 两个节点 已经在 并查集 中，那就说明，添加当前的边就会成环，所以跳过当前边
  4. 重复 2、3 即可

总结

prim 的 时间复杂度是 O(n^2)，其中 n 为节点个数
kruskal 中，快排为 O(nlogn) 的时间复杂度，并查集不路径压缩是 O(logn) 路径压缩接近 O(1)，所以 kruskal 时间复杂度为 O(nlogn)。其中 n 为 边个数

显然 当点少的时候，可以用 prim；当边少的时候（稀疏）用 kruska 快
