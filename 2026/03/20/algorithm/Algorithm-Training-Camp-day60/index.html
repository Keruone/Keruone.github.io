题目解析

Floyd 97. 小明逛公园

Floyd 算法 用来解决 多个点之间的最短距离。

之前的算法，你有没有发现，遍历半天都是计算从 点A 到 点B 的最短距离？
那突然之间，我想知 A->B C->D D->F… 的距离，咋办？重复循环码？那多费劲啊

对此，该 Floyd 登场了！
它可以一次，计算所有点之间的最短距离
一般来说，如果 dijkstra、bellman-ford要同样计算全部点之间的最短距离，要在它们基础上遍历，时间复杂度 粗略估计都得加 N^2，这就比 N^3 的floyd慢了!

基本思路介绍

它的想法有动态规划的成分：

  • 下标含义：dp[i][j][k] 表示 从 节点i 到 节点j，在允许经过 节点[1…k]时，所可以达到的最短距离
  • 递归公式：dp[i][j][k] = min(dp[i][j][k-1], dp[i][k][k-1] + dp[k][j][k-1])

    表示 从 i到j 不经过节点k时的路径 和 经过节点k时的路径，哪个短

    对于k，可以这么想：

    • 一开始我只有两个节点 i j 直接相连时候的长度
    • 现在，我想尝试一下，让 i 先经过 节点1，再到 j，距离是否会变短
      • 如果会，我就知道了 从 i 到 j 有更短的路径 那我的 dp[i][j][1]就可以更新为这个更短的值
      • 如果不会，那也没事，dp[i][j][1]我就记录原来的长度
    • 按照这个想法，我把所有的节点先都考虑 到1 再到目的地遍历一次
    • 现在，我要开始考虑一下，从 i 到 j 经过 节点2，是否会更短一点呢？
      • 那对此，我应该要将 i到j的最短距离 与 i到2的最短距离+2到j的最短距离 比较
      • 而其中 i到2的最短距离 我已经在上一轮循环中判断过一次了，知道时 i->1->2近还是 i->2 近，存储在 dp[i][2][1] 中
      • 同理，我也知道是 2->j 近 还是 2->1->j 近，存储在 dp[2][j][1] 中
        • 注意，这里 因为相当于 全局限制，只允许经过 1点 和 2点，所以 1、2本身和任何节点到1、2都是满足这个条件的
      • 所以有 dp[i][j][2] = min(dp[i][2][1] + dp[2][j][1], dp[i][j][1])
    • 最后，再向外推广，随着允许的节点越来越多，就得到了我们的递推公式
  • 初始化：dp[i][j][0] = 边权 只记录 直接相连的 两个节点之间的距离。如果没有边相连，初始化为无穷。
  • 递归方向：外层先从小到大遍历k，再遍历i、j。

优化

其实你观察，可以发现 k 每次使用的都是 k-1 的数值，所以其实可以从三维压缩到二维的

一般 dp 降维后，会有某层循环遍历方向的变化，但是这个没有，解释如下：

  • 举例 在一轮中 ，比如 dp[i][j][k] ，我会考虑 i->k->j
  • 需要计算 dp[i][k][k-1] + dp[k][j][k-1]
  • 一般可能会担心，如果 dp[i][k][k-1] 或者 dp[k][j][k-1] 被更改了怎办呀
  • 但是你细想，对于 dp[i][k][k] 的数值，不是肯定就是 dp[i][k][k-1] 的数值嘛，因为不可能走 从 i->k 变成 i->k->k
  • 所以我们再折回去看看dp[i][j][k] = min(dp[i][j][k-1], dp[i][k][k-1] + dp[k][j][k-1])：
    • dp[i][k][k-1] 不会改变
    • dp[k][j][k-1] 不会改变
    • dp[i][j][k-1] 其实修改的是自己，而别人只会使用 某个值到 k，用不到其它节点的

A* 127. 骑士的攻击

现在介绍 A*
假设你在一条特别宽广的空地上，给你一个遥远的目标，你怎么找到最短路径呢？bfs？是最短路径，但是吧，你90%的探索全是无用功，太浪费时间了！

那咋办？让我们的 bfs 更有倾向性！

基本思路介绍

先回顾一下 一般的 bfs
我们使用 队列 queue，存储每一次循环遍历的节点，然后将该点下一轮可以达到的位置加入队列末尾。

这里我们可以看到，没有倾向性，导致它一直在发散。
那我们要不，我们估算一下和终点的距离？可以啊，我给他暂记为 h。
然后，我再加上实际我已经走过的距离g，两者合起来作为指标 f。
即 f = g + h

或许沿途有障碍，或许有你的行动限制，但是无论怎么说我估算一个大体位置总没问题啊！

现在我们知道了一个评判标准，哼哼！但是代码中，怎么让他的排列有能够根据我的估算结果更有倾向性嘞？
这个时候，就可以使用 priority_queue，来构建 最大/小堆！
利用 它自动 向上/下 的特性，每次我们将新的点位塞入 queue中，不久自动给咱们按照 我们的估算标准排序了嘛！
那这个时候，我们再从堆顶部取出的，不就是一定程度上可以反应咱们最短路径方向的下一步了吗。good！

常用的距离估算，有 曼哈顿距离、欧氏距离、切比雪夫距离。

最小生成树 & 拓扑

核心目标：构建图的结构（连接所有点且代价最小，或者确定点的先后顺序），而不是计算两点间的具体距离。

算法 全称 核心思想 适用场景 关键词
Prim Prim’s Algorithm 加点法。从一个点开始，每次找离当前生成树最近的一个点加入。 稠密图 (E ≈ V^2) 贪心、类似Dijkstra、维护点到集合距离
Kruskal Kruskal’s Algorithm 加边法。把所有边排序，从小到大选，只要不构成环就加入。（注意，使用并查集判断是否构成 环） 稀疏图 ( E ≈ V) 贪心、并查集 (Union-Find)、判环
拓扑排序 Topological Sort 排序法。在有向无环图 (DAG) 中，将节点排成线性序列，满足所有箭头方向。 任务调度、依赖关系、检测环 入度表、BFS/Kahn算法、DFS

共同点：

  • 它们都不关心“从A到B的最短距离是多少”。
  • Prim 和 Kruskal 都是贪心算法。
  • 拓扑排序只针对有向无环图 (DAG)。

最短路径 (Shortest Path)

算法 全称 核心思想 适用场景 关键词
Dijkstra Dijkstra’s Algorithm 贪心+BFS。每次选离起点最近且未确定的点，更新其邻居。 非负权图 (最常用) 优先队列、贪心、单源最短路径
Bellman-Ford Bellman-Ford Alg. 动态规划/松弛。对所有边进行 $ V-1 $ 轮松弛操作。（但是考虑到有些操作做了等于没做，所以有了SPFA） 含负权边、检测负环 暴力松弛、 $ O(VE) $ 、单源、负环检测
Floyd Floyd-Warshall Alg. 动态规划。枚举中间点 $ k $ ，逐步更新任意两点 $ i, j $ 的距离。 多源最短路径、数据量小 ( $ N \le 500 $ ) 三重循环、 $ O(N^3) $ 、允许负权 (无负环)
Astar A-Star Search 启发式搜索。Dijkstra + 估价函数 $ h(n) $ ，优先搜索“最有希望”的方向。 寻路问题 (地图、游戏)、需要快速找到单条路径 $ f=g+h $ 、启发式、优先队列、不一定最优(若h不准)

核心都是为了解决“距离/代价最小化”问题。
Dijkstra、Bellman-Ford、A* 通常用于单源（从一个起点出发）。
Floyd 是唯一的多源（一次性算出所有点对）算法。

区别关键：

  • 有负权吗？
    • 有则用 Bellman-Ford / Floyd。
  • 要算所有点对吗？
    • 是则用 Floyd。
  • 需要极速寻路且有坐标信息？
    • 用 A*。
  • 普通非负权单源？
    • 首选 Dijkstra。
