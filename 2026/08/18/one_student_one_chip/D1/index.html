不停计算的机器

取指、译码、执行

YEMU

  • 指令和数据，都存放在 M 中。
  • 如果读取到的不是规定的 switch 中的语句，就视作结束，halt = 1
  • 使用 union 来确保一个指令可以被译码为不同的内容
  • 所以处理流程就是 取指、译码、执行

可以观察到 源码 中，union 的顺序 似乎是跟 实际的指令顺序是相反的
核心原因：从低位往高位填充
- 在我们常用的 x86/ARM 架构（小端模式）下，GCC 编译器在分配位域时，是从低位（LSB，即最右边的 bit 0）向高位（MSB，即最左边的 bit 7）依次填充的。
- 所以，结构体中成员的书写顺序决定了它们在物理字节中从低到高的排列：

函数解析

这是一个 匹配函数，将

  • 首先，我们先专注于对于单独的某一位进行考虑，即 macro(i)

    • key 表示 具体的数值
    • mask 表示需要的位，使用掩码表示，之关系非 ? 的字符
    • shift 表示 需要偏移的长度

  • 这里你会注意到一件事，如果 shift 不是 ?，会进行置零，这样做的目的是说明：shift 用于计算在匹配的末端偏移的个数。（因为 key 和 mask 的匹配标准会导致中间或者末尾仍可以存在连续的 '?'。所以需要通过 shift 至少把末尾的可以移除）

    • **中间的 ?**：mask 会把它抹掉（对应位为 0），这样在比较时就不会受到中间随机寄存器等变数字段的影响。
    • 末尾的 ?：因为对匹配结果没有影响，直接通过 _shift 统计个数，最后统一右移踢掉，让 key 和 mask 变得更紧凑。

对于除法，注意：

  • 除0处理：RISC-V 规范规定除零时结果为全 1（即 -1，0xFFFFFFFF），但 C 语言除零是未定义行为，会直接崩溃。
  • 溢出处理：当 rs1 = 0x80000000（即 -2^31）且 rs2 = 0xFFFFFFFF（即 -1）时，-2^31 / -1 = 2^31 超出有符号 32 位范围。RISC-V 规范要求此时结果为 0x80000000。
