课程概览与shell

  1. .ls 的 -l 选项（flag）作用是什么？运行 ls -l / 并观察输出。每一行最前面的 10 个字符分别代表什么？（提示：man ls）
  • total：和后文比较后，你可以发现，其实就是 文件实际占用的磁盘空间
  • 前 10 字符表示：文件权限
    • 在 info ls 中找到，使用 s pattern ，其中 pattern 输入 Note File permissions，然后跳转 info 中的链接。再进入 Mode Structure 介绍。
    • 第 1 位 表示是 文件 还是 目录
    • 第 2-4 位 表示 文件拥有者 的 可读可写可执行 权限
    • 第 5-7 位 表示 用户同组的其他成员 的 可读可写可执行 权限
    • 第 8-10 位 表示 其他每个用户 的 可读可写可执行 权限

很诡异啊，这咋平白无故多出来了 6K的空间占用？

关键在于:ls -l 顶部的 total 行报告的是文件实际占用的磁盘空间(也就是 du 看到的、按文件系统块分配的大小),而每行 size 列显示的是文件的逻辑大小(apparent size) 向上取整到 K。这两个数不是一回事。

对此，我的文件系统(ext4)的块大小是 4K,文件只能按整块分配。
/dev/sda3 ext4 78G 15G 59G 20% /

  • hello.txt 逻辑大小不到 1K,显示为 1K,但它至少占用一个完整的 4K 块 → 实际占 4K,多出 3K。
  • man ls.txt 逻辑大小在 8K~9K 之间,显示为 9K,但需要 3 个 4K 块才放得下(2 块只有 8K 不够)→ 实际占 12K,多出 3K。
  • 两个文件各多出 3K,加起来正好就是那 6K。
  1. 在命令 find ~/Downloads -type f -name "*.zip" -mtime +30 中，*.zip 是一个 「glob」。什么是 glob ？新建一个测试目录并创建一些文件，试试 ls *.txt 、ls file?.txt 、ls {a,b,c}.txt 等模式。参见 Bash 手册中的 Pattern Matching 。
  • -type 表示文件类型
    • -f regular file，普通文件
  • glob 表示 通配符模式
  1. '单引号'、"双引号" 和 $'ANSI 引号' 有什么区别？写一条命令，输出一个同时包含字面量 $ 、! 和换行符的字符串。参见 Quoting 。
  • 单引号里面包的是啥就当啥，不做任何转换转义解释
  • 双引号大部分字符保留原义，仅 $、`、\、!（历史扩展开启时）有特殊功能。
  • $'字符串' 是特殊单引号语法，会按照 ANSI C 标准解析字符串内的反斜杠转义符，并将转义序列替换为对应实际字符。
    ! 在 Shell 中的作用：历史扩展 (History Expansion)。Shell 会记录你执行过的所有命令（命令历史），! 是用来快速调取、复用历史命令的专用符号，这就叫历史扩展。
    假设你历史里执行过这些命令：

① !数字 执行指定序号的历史命令

② !字符串 执行最近一条以该字符串开头的命令

③ !! 快速执行上一条命令（高频）

④ !$ 取上一条命令的最后一个参数

在以下说明中，若省略文件描述符编号，且重定向操作符的首字符为 **<**，则该重定向指向标准输入（文件描述符 0）；若重定向操作符的首字符为> ，则该重定向指向标准输出（文件描述符 1）。
重定向后面的内容正常执行全套扩展、替换、解析；但最终结果必须是单个目标（单个文件 / 单个路径）；一旦解析出多个单词 / 多个文件，直接报错。
重定向按书写顺序依次执行，后序操作基于前序的描述符状态；顺序不同，最终数据流走向也不同。

  • ls > dirlist 2>&1
    • 标准输出1与错误输出2都输出到 指定文件。
    • 首先 >重定向 标准输出；（类似此时赋值 标准输出1=dirlist
    • 接着将 错误输出 输出到 同样的输出位置（类似此时赋值 错误输出2=标准输出1，即错误输出2=dirlist
  • ls 2>&1 > dirlist
    • 标准输出1输出到 指定文件，错误输出2 重定向到屏幕。
    • 错误输出2 = 标准输出1
      /dev/fd 是一个伪文件系统目录，用来把当前进程的所有文件描述符（fd）暴露成 “文件路径”，方便用路径方式操作 fd。
      二者互为软链接，**/dev/stdin/stdout/stderr 等价于 /dev/fd/0/1/2**。

数字在前代表要重定向的来源流，符号后是接收内容的目的地。
2>&1 中 & 作用是标记后面数字为文件描述符，避免 Shell 把它当成普通文件。
The general format for redirecting input is: [n]<word
The general format for redirecting output is: [n]>[|]word(*注意，如果开了 noclobber 防覆盖模式，你就要注意你写入的文件并没有提前创建了)
重定向标准输出和标准错误有 &>word 与 >&word 两种写法，优先用前者，二者等价于 >word 2>&1。
>> 代表追加写入，用法逻辑和前文一致。

Here-doc 标准格式：

  1. << 标记名：告诉 Shell，接下来直到「单独一行写标记名」为止，所有内容都当作命令的标准输入。
  2. 中间的行：真正要输入的内容。
  3. 最后单独一行的 标记名：结束符，代表读取终止，这一行本身不会被传给命令、也不会打印出来。
  4. 若标记名（word）包含引号，分隔符为去除引号后的内容，Here-doc 内所有内容不会做任何解析展开；若标记名无引号，分隔符即为原内容，文档文本规则等同于双引号字符串：会执行参数展开、命令替换、算术展开，\换行 原样识别，需用 \ 转义 \、$、`，双引号则无特殊作用。

Here 文档以[n]<<[-]分隔符定义输入范围，引号控制内容是否解析变量 / 命令，<<-可剔除行首制表符，无引号时行尾\会合并换行。

复制文件描述符 >& / <& 含义：把一个文件描述符的读写通道复制一份，新旧描述符指向同一个数据源 / 目标，二者独立存在、互不关闭。(经典的 2>&1 就是)

移动（迁移）文件描述符 digit- 含义：将描述符转移到新编号，转移完成后，原描述符会被直接关闭，不再可用。

执行后仅 >&3 的内容会打印，直接 echo 无效果。

[n]<>文件 会让该文件描述符对目标文件兼具读、写能力。即做输入，又做输出。

  1. $? 保存上一条命令的退出状态（0 表示成功）。&& 仅在前一条成功时执行后一条；|| 仅在前一条失败时执行后一条。写一个一行命令：仅当 /tmp/mydir 不存在时才创建它。参见 Exit Status 。

  2. 为什么 cd 必须是 Shell 内建命令，而不能是独立程序？（提示：想想子进程能影响和不能影响父进程的哪些状态。）

  • 内建命令：跑在 Shell 自身进程里，无子进程。
  • 外部命令：新建子进程运行，子进程改不了父进程状态。
  • 子进程不能影响父进程，所以如果作为独立程序，修改后也只会修改子进程路径，不会修改父进程路径。所以必须是 Shell 修改 Shell 本身，所以得是内建命令。
  1. 写一个脚本，接收文件名参数（$1），用 test -f 或 [ -f ... ] 检查该文件是否存在，并根据结果输出不同提示。参见 Bash Conditional Expressions 。

* 注意，这里 $1 表示的不是标准输出，而是第一个参数

[ 本身就是 Shell 内置命令（全称 test），不是单纯的标点符号。
[ 条件 ] 和 test 条件 完全等价。
注意，[ ] 前后都要留出空格

  • find path -name *.sh 其实就已经可以找到 *.sh 文件了，但是 shell 会先解析通配符，导致find对于空格的处理出问题。对此，加上双引号就可以避免，这样，"*.sh"就从 shel l解析，变成了 find 解析。

    • xargs命令的基本用法：
      xargs通常与管道命令一起使用，其基本格式如下：
      somecommand | xargs [option] command
      其中，_somecommand_是任意命令，_xargs_后面跟随的是需要执行的命令。xargs会将前一个命令的输出作为后一个命令的参数。

1. -print0 → find 的选项

- 默认 find：**换行符 `\n` 分隔每个文件名**
- `-print0`：改用 **空字符 `\0`（ASCII 0）** 分割文件名输出

Linux 文件名不允许包含 \0，所以\0是绝对安全的分隔符。
2. -0 → xargs 的选项（全称--null）

- 默认 xargs：以**空格、换行、制表符**切割输入，遇到文件名带空格就会把一个文件劈成多个参数（报错）
- `-0`：约定输入用`\0`做分隔符，按`\0`切分参数，**空格 / 换行全部当成文件名的普通字符**
