主要记录一下必做题，以及最重要的，搭出来了自己的第一个 sCPU !

RV32I

位于 第二章 Chapter 2. RV32I Base Integer Instruction Set, Version 2.1

  1. PC寄存器的位宽是多少?

    • 32bit

  2. GPR 共有多少个? 每个 GPR 的位宽是多少?

    • 32 个，每个32 bit

  3. R[0]和sISA的R[0]有什么不同之处?

    • RV32I 的 R[0] 强制全部内容为 0

  4. 指令编码的位宽是多少? 指令有多少种基本格式?

    • 32bit

    • 四种基本格式 R/I/S/U

    • B 格式属于 S 的变体

    • J 格式属于 U 的变体

  5. 在指令的基本格式中, 需要多少位来表示一个GPR? 为什么?

    • 5bit，32 个 GPR ，得 5bit 二进制才能表示完

  6. add指令的格式具体是什么?

    • funct7 rs2 rs1 funct3 rd opcode

    • 其中 funct7 funct3 为 表示 add 的内容

    • “0000000 rs2 rs1 000 rd 0110011 ADD” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 554)

  7. 还有一种基础指令集称为RV32E, 它和RV32I有什么不同?

    • RV32I 表示 整数 32 位

    • E表示服务于 Embedded Systems 嵌入式

    • RV32E和RV64E分别是RV32I和RV64I的精简版本：唯一的改动是将整数寄存器数量减少至16个。

minirv 处理器

  • PC初值为0

  • GPR数量与RV32E中定义的GPR数量一致

  • 支持如下8条指令: add, addi, lui, lw, lbu, sw, sb, jalr

  • 其他的ISA细节与RV32I相同

实现的指令

ADDI

参考 2.4.1 可以看到 addi 格式

ADDI 将符号扩展的 12 位立即数与寄存器 rs1 相加。算术溢出被忽略，结果仅为结果的低 XLEN 位。ADDI rd, rs1, 0 用于实现汇编伪指令 MV rd, rs1。

详细观察 Chapter 34，可以找到

“imm[11:0] rs1 000 rd 0010011 ADDI” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 554)

即：

  • [31:20]: imm[11:0]

  • [19:15]: rs1

  • [14:12]: func3 000

  • [11:7]: rd

  • [31:20]: opcode 0010011

参考：

“ADDI” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 26)

JALR

参考 2.5.1 可以看到 jalr 格式就可以

间接跳转指令JALR（跳转并链接寄存器）采用I型编码。目标地址通过将符号扩展的12位I型立即数与寄存器rs1相加，再将结果的最低有效位清零得到。跳转指令的下一条指令地址（pc+4）被写入寄存器rd。若无需保存返回地址，可将寄存器x0用作目标寄存器。

“The indirect jump instruction JALR (jump and link register) uses the I-type encoding. The target address is obtained by adding the sign-extended 12-bit I-immediate to the register rs1, then setting the least-significant bit of the result to zero. The address of the instruction following the jump (pc+4) is written to register rd. Register x0 can be used as the destination if the result is not required.” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 28)

ADD

R[rd] = R[s1] + R[s2]

LUI

“LUI (load upper immediate) is used to build 32-bit constants and uses the U-type format. LUI places the 32-bit U-immediate value into the destination register rd, filling in the lowest 12 bits with zeros.” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 27)

LUI（加载高位立即数）用于构建32位常量，采用U型格式。LUI将32位U型立即数存入目标寄存器rd，并将最低12位填充为零。

LUI 可以和 ADDI 搭配使用，构建并写入一个 32 bit 的数。即先 LUI，再 ADDI，因为 LUI 会覆盖掉低 12 bit 全为 0。不过需要注意，如果 ADDI 的数字最高位 为 1，这会导致 ADDI 执行中进行符号扩展，将高位都填充为1。此时你会发现实际相加的结果，比你预想的 少 1（因为要抵消到高位的 1…1，需要 LUI 最低位 的 1 来抵消）。对此，如果你的 ADDI 高位为1，则你的 LUI 写入的 imm 需要 加 1。

LW & LBU

“Load and store instructions transfer a value between the registers and memory. Loads are encoded in the I-type format and stores are S-type. The effective address is obtained by adding register rs1 to the sign-extended 12-bit offset. Loads copy a value from memory to register rd. Stores copy the value in register rs2 to memory.

加载与存储指令在寄存器与内存之间传输数据。加载指令采用I型格式编码，存储指令采用S型格式编码。有效地址通过将寄存器rs1与符号扩展后的12位偏移量相加获得。加载指令将内存中的值复制到寄存器rd，存储指令将寄存器rs2中的值复制到内存。

The LW instruction loads a 32-bit value from memory into rd. LH loads a 16-bit value from memory, then sign-extends to 32-bits before storing in rd. LHU loads a 16-bit value from memory but then zero extends to 32-bits before storing in rd. LB and LBU are defined analogously for 8-bit values. The SW, SH, and SB instructions store 32-bit, 16-bit, and 8-bit values from the low bits of register rs2 to memory.” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 32)

LW指令从内存加载32位值至rd。LH指令从内存加载16位值，经符号扩展至32位后存入rd。LHU指令从内存加载16位值，经零扩展至32位后存入rd。LB与LBU指令对8位值作类似定义。SW、SH与SB指令分别将寄存器rs2低位的32位、16位与8位值存储至内存。

EEI

“Regardless of EEI, loads and stores whose effective addresses are naturally aligned shall not raise an address-misaligned exception. Loads and stores whose effective address is not naturally aligned to the referenced datatype (i.e., the effective address is not divisible by the size of the access in bytes) have behavior dependent on the EEI.

An EEI may guarantee that misaligned loads and stores are fully supported, and so the software running inside the execution environment will never experience a contained or fatal addressmisaligned trap. In this case, the misaligned loads and stores can be handled in hardware, or via an invisible trap into the execution environment implementation, or possibly a combination of hardware and invisible trap depending on address.

An EEI may not guarantee misaligned loads and stores are handled invisibly. In this case, loads and stores that are not naturally aligned may either complete execution successfully or raise an exception. The exception raised can be either an address-misaligned exception or an access-fault exception. For a memory access that would otherwise be able to complete except for the misalignment, an access-fault exception can be raised instead of an address-misaligned exception if the misaligned access should not be emulated, e.g., if accesses to the memory region have side effects. When an EEI does not guarantee misaligned loads and stores are handled invisibly, the EEI must define if exceptions caused by address misalignment result in a contained trap (allowing software running inside the execution environment to handle the trap) or a fatal trap (terminating execution).” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 32)

无论采用何种执行环境接口（EEI），有效地址自然对齐的加载与存储操作不得引发地址未对齐异常。有效地址未按所引用数据类型自然对齐（即有效地址不能被访问字节大小整除）的加载与存储操作，其行为取决于EEI。

EEI可保证完全支持未对齐的加载与存储操作，因此执行环境内运行的软件永远不会遇到包含式或致命性地址未对齐陷阱。在此情况下，未对齐的加载与存储可通过硬件处理，或通过执行环境实现中的不可见陷阱处理，亦可能根据地址采用硬件与不可见陷阱的组合方式。

EEI可能不保证未对齐的加载与存储操作能被不可见地处理。此时，未自然对齐的加载与存储操作可能成功完成执行，也可能引发异常。所引发的异常可以是地址未对齐异常或访问故障异常。对于本可完成但因未对齐而受阻的内存访问，若该未对齐访问不应被模拟（例如对该内存区域的访问具有副作用），则可引发访问故障异常而非地址未对齐异常。当EEI不保证未对齐的加载与存储操作能被不可见地处理时，EEI必须定义由地址未对齐引发的异常是导致包含式陷阱（允许执行环境内运行的软件处理该陷阱）还是致命性陷阱（终止执行）。

不对齐访存

RISC-V 关于  存储器的规定

一个 RISC-V 硬件线程 拥有一个 单一的 字节可寻址 地址空间，用于所有内存访问。内存中的一个字 定义为32位(4字节)。相应地，半字为16位(2字节)，双字为64位(8字节)，四字为128位(16字节)。内存地址空间是循环的，因此地址 2^XLEN-1 处的字节与地址零处的字节 相邻。因此，硬件执行的内存地址计算忽略溢出，而是按模进行回绕。

  1. 真正的“防越界”有 MMU/页表负责，不靠地址加法器 你可能担心：如果地址回绕到 0x00000000，岂不是可以静默地破坏内核数据结构或别的程序内存？ 但实际上，现代系统（有 MMU 的情况下）访问内存前还要经过地址转换和权限检查：

    • 即使计算出的地址回绕到了 0x00000000，如果这个地址不在当前进程的页表里，或者没有读写权限，MMU 会触发 Page Fault，而不是真的去写物理内存。

    • 如果回绕后的地址恰好落到了用户空间某个已映射的区域，那确实会静默访问——但这本质上和普通的数组越界是同一类 bug，是软件（编译器/程序员）需要避免的事情。

    • 换句话说：地址回绕解决的是“算术怎么算”的问题，内存保护解决的是“能不能访问”的问题。 两者分层处理。

  2. 统一数据路径的设计 CPU 里的地址计算通常就是拿普通的整数 ALU 做的（effective_address = base + offset）。如果数据运算天然就是模 2322^{32}232 回绕的，而地址运算要求额外检查溢出，那就意味着：

    • 要么给 ALU 增加额外的溢出检测输出和异常处理逻辑；

    • 要么给地址计算单独做一条特殊通路。

    • 无论哪种，都违背了“简单统一”的原则。让地址计算和数据计算遵循同样的模运算规则，硬件设计更干净。

其他有意思的地方

  1. 可以发现， RISC_V 将所有寄存器放在相同的位置，这样硬件电路就很方便了

  2. 如果有立即数，都在最高位，这样方便从 12 bit 到 32 bit 时候，高位正数补0 负数补1

  3. 此外，对于立即数，如 S-Type，可以发现，立即数被拆分开来了，但是拼接起来仍然是立即数

  4. 立即数的分割是非对称的，常规指令 12bit，还有一个特殊指令包含高位 20bit

“The RISC-V ISA keeps the source (rs1 and rs2) and destination (rd) registers at the same position in all formats to simplify decoding. Except for the 5-bit immediates used in CSR instructions (Chapter 7), immediates are always sign-extended, and are generally packed towards the leftmost available bits in the instruction and have been allocated to reduce hardware complexity. In particular, the sign bit for all immediates is always in bit 31 of the instruction to speed sign-extension circuitry.” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 23)

“Decoding register specifiers is usually on the critical paths in implementations, and so the instruction format was chosen to keep all register specifiers at the same position in all formats at the expense of having to move immediate bits across formats (a property shared with RISC-IV aka. SPUR (Lee et al., 1989)).” (“The RISC-V Instruction Set Manual Volume I: Unprivileged Architecture”, p. 24)
